# Button Components

> "Every action is an invitation to explore."

---

# Purpose

Buttons are the primary interaction elements in AstroAlert.

They allow users to perform actions, continue discoveries and interact with astronomical experiences.

Buttons should not only communicate functionality.

They should communicate intention.

Every button should make users understand:

- What will happen.
- Why they should interact.
- Where the action will take them.

The purpose of AstroAlert buttons is to create interactions that feel:

- Clear.
- Elegant.
- Responsive.
- Natural.

---

# Content

# Button Philosophy

Buttons in AstroAlert follow the Cosmic Glass philosophy:

Actions should feel like points of light within the interface.

They should attract attention when necessary, but they should never overpower the experience.

The universe is the focus.

The interface only guides exploration.

---

# Button Types

AstroAlert uses a limited number of button types.

Too many variations create inconsistency.

---

# Primary Button

## Purpose

Used for the most important action on a screen.

Examples:

- Explore Planet.
- Start Observation.
- View Event.
- Discover More.

## Characteristics

- Highest visual priority.
- Strong contrast.
- Clear action wording.

## Usage

Only one primary action should usually exist per section.

The user should immediately understand the main next step.

---

# Secondary Button

## Purpose

Used for supporting actions.

Examples:

- View Details.
- Learn More.
- Compare.

## Characteristics

- Less visual weight.
- Supports the primary action.

Secondary actions should never compete with primary actions.

---

# Ghost Button

## Purpose

Used for subtle actions.

Examples:

- Cancel.
- Return.
- Additional options.

## Characteristics

- Minimal appearance.
- Maintains visual calm.

---

# Icon Button

## Purpose

Used when an action can be represented clearly by an icon.

Examples:

- Search.
- Settings.
- Favorite.
- Share.

## Rules

Icons must be understandable.

Unknown icons should include labels.

---

# Button Anatomy

Every button consists of:

## Label

The action being performed.

Should be:

- Short.
- Clear.
- Specific.

Avoid:

"Click here"

Prefer:

"Explore Mars"

---

## Icon

Optional.

Used to improve understanding.

Icons should support meaning, not decoration.

---

## State

Buttons communicate their current condition.

---

# Button States

## Default

Normal appearance.

The button is available for interaction.

---

## Hover

Provides confirmation that the element is interactive.

The change should be subtle.

---

## Active

Shows the moment of interaction.

The response should feel immediate.

---

## Disabled

Used when an action is unavailable.

The user should understand why.

---

## Loading

Used when an action requires processing.

The interface should communicate progress.

---

# Button Behavior

## Clear Feedback

Every interaction must provide a response.

Users should know their action was recognized.

---

## Smooth Transition

Changes between states should feel natural.

Motion should follow the Motion System principles.

---

## Accessible Interaction

Buttons must support:

- Keyboard navigation.
- Clear focus states.
- Screen readers.

---

# Button Language

The text inside buttons should encourage exploration.

Preferred:

- Explore
- Discover
- Observe
- Learn
- View
- Track
- Continue

Avoid:

- Submit
- Execute
- Process

Unless technically necessary.

---

# Button Placement

Buttons should appear where users naturally expect them.

Examples:

Primary actions:

- Near important information.

Exploration actions:

- After discovery content.

Supporting actions:

- Secondary positions.

---

# Visual Rules

Buttons should:

- Respect spacing rules.
- Follow color system rules.
- Use typography rules.
- Follow motion principles.

A button should never look like it belongs to another product.

---

# Design Implications

Button components affect:

- Navigation.
- Cards.
- Forms.
- Modals.
- Pages.
- Interactive experiences.

Every action in AstroAlert should use an existing button pattern.

New button styles should only be created when a new interaction purpose exists.

---

# Final Statement

Buttons are small elements with a big responsibility.

They are the moments where curiosity becomes action.

A good button does not demand attention.

It invites exploration.
