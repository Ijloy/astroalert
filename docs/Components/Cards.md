# Card Components

> "Every card is a small window into the universe."

---

# Purpose

Cards are one of the fundamental components of AstroAlert.

They organize astronomical information into clear and meaningful experiences.

Cards help users discover:

- Celestial objects.
- Scientific information.
- Events.
- Observations.
- Educational content.

A card is not only a container for information.

It is an invitation to explore.

---

# Content

# Card Philosophy

AstroAlert cards follow the Cosmic Glass principle:

Information should feel contained, but never trapped.

Cards create structure while maintaining the feeling of space.

They should feel like:

- Floating information panels.
- Scientific instruments.
- Windows into discovery.

They should not feel like:

- Generic website boxes.
- Heavy UI containers.
- Crowded information blocks.

---

# Card Anatomy

Every card is composed of intentional layers.

---

# Visual Layer

## Purpose

Create immediate recognition.

Contains:

- Image.
- Illustration.
- Astronomical visualization.

The visual element should communicate identity.

Examples:

Mars card:

- Planet image.
- Name.
- Main characteristic.

Eclipse card:

- Event visualization.
- Date.
- Visibility information.

---

# Information Layer

## Purpose

Explain the most important information.

Contains:

## Title

The main identifier.

Examples:

"Mars"

"Total Solar Eclipse"

"International Space Station"

---

## Description

A short explanation.

The first sentence should create understanding.

---

## Metadata

Supporting information.

Examples:

- Distance.
- Date.
- Temperature.
- Location.
- Visibility.

---

# Action Layer

## Purpose

Allow exploration.

Examples:

- Explore.
- Learn More.
- Track.
- Observe.

Actions should always have clear purpose.

---

# Card Types

AstroAlert uses different card variations depending on the experience.

---

# Discovery Card

## Purpose

Introduce astronomical objects or topics.

Examples:

- Planets.
- Galaxies.
- Missions.

Characteristics:

- Strong visual identity.
- Minimal information.
- Encourages exploration.

---

# Information Card

## Purpose

Display scientific data.

Examples:

- Planet measurements.
- Telescope information.
- ISS statistics.

Characteristics:

- Clear hierarchy.
- Data-focused.

---

# Event Card

## Purpose

Present astronomical events.

Examples:

- Eclipse.
- Meteor shower.
- Planet alignment.

Characteristics:

Shows:

- Event name.
- Date.
- Visibility.
- Importance.

---

# Observation Card

## Purpose

Help users interact with the real sky.

Examples:

- Visible planets tonight.
- Telescope recommendations.

Characteristics:

Focused on action.

---

# Card States

## Default

Normal state.

The card is available for exploration.

---

## Hover

Creates subtle feedback.

Possible changes:

- Slight elevation.
- Light interaction.
- Image depth.

The effect should be elegant.

---

## Selected

Used when a user chooses an object.

The card should clearly communicate focus.

---

## Loading

Used when astronomical data is being retrieved.

The loading state should preserve the cosmic feeling.

---

# Card Information Hierarchy

Every card should prioritize:

1. What is this?
2. Why does it matter?
3. What can I do next?

The user should understand a card within seconds.

---

# Card Content Rules

## Rule 1

Do not overload cards.

A card is an introduction.

Not a complete article.

---

## Rule 2

The most important information appears first.

---

## Rule 3

Images must have meaning.

Avoid decorative images without purpose.

---

## Rule 4

Scientific accuracy is always required.

---

# Card Interaction

Cards should encourage exploration.

Possible interactions:

- Open details.
- Compare objects.
- View related content.
- Start an experience.

Interactions should feel natural.

# Responsive Behavior

Desktop:

Cards can provide richer exploration layouts.

Mobile:

Cards prioritize:

- Main image.
- Important information.
- Primary action.

The experience should remain lightweight.

---

# Accessibility

Cards must provide:

- Clear text hierarchy.
- Alternative descriptions for images.
- Keyboard navigation when interactive.
- Visible focus states.

---

# Design Implications

Cards influence:

- Pages.
- Dashboards.
- Discovery sections.
- Educational experiences.

New card types should only exist when they represent a new information purpose.

---

# Final Statement

Cards are not simple UI elements.

They are moments of discovery.

Every card should make the user think:

"I want to know more."
