# Layout System

> "A universe without structure would be impossible to explore."

---

# Purpose

The AstroAlert Layout System defines how information, experiences and visual elements are organized throughout the platform.

Layout is not only about positioning elements on a screen.

It creates a journey.

It determines:

- What users see first.
- What information receives importance.
- How users move through experiences.
- How the universe is presented.

The purpose of the layout system is to create interfaces that feel:

- Natural.
- Balanced.
- Immersive.
- Easy to understand.

---

# Content

# Layout Philosophy

The universe has structure.

Planets orbit stars.

Galaxies form patterns.

Systems connect with each other.

AstroAlert follows the same principle.

Every element should have a place.

Every section should have a purpose.

Every screen should guide the user toward discovery.

---

# Visual Structure

AstroAlert interfaces are built using three main layers.

---

# Layer 1 — Cosmic Environment

The background layer creates the atmosphere.

Purpose:

Provide depth and emotion.

Contains:

- Space backgrounds.
- Subtle gradients.
- Atmospheric effects.
- Large astronomical imagery.

Rules:

The environment should support the content.

It should never distract from it.

---

# Layer 2 — Information Layer

The information layer contains the main experience.

Purpose:

Present astronomical information clearly.

Contains:

- Cards.
- Data.
- Visualizations.
- Explanations.
- Interactive elements.

This is where users understand the universe.

---

# Layer 3 — Interaction Layer

The interaction layer contains actions.

Purpose:

Allow users to explore.

Contains:

- Controls.
- Navigation.
- Filters.
- Tools.
- User actions.

Interactions should always feel intentional.

---

# Screen Composition

Every AstroAlert screen should answer three questions.

## Where am I?

The user should immediately understand the current section.

Examples:

- Planets.
- Eclipses.
- Telescope.
- ISS.

---

## What is important?

The most relevant information should always appear first.

Important information should never be hidden.

---

## What can I do next?

Every screen should naturally suggest the next action.

Examples:

- Explore a planet.
- View an event.
- Track the ISS.
- Start an observation.

---

# Information Hierarchy

AstroAlert follows a clear hierarchy.

## Primary Information

The most important information on the screen.

Examples:

- Current astronomical event.
- Planet visibility.
- ISS location.

This should receive the strongest visual attention.

---

## Secondary Information

Supporting details.

Examples:

- Scientific explanation.
- Additional measurements.
- Historical information.

---

## Tertiary Information

Extra context.

Examples:

- Sources.
- Metadata.
- Technical details.

---

# Navigation Philosophy

Navigation should feel like exploration.

It should not feel like browsing a traditional website.

The user should feel like they are moving between different areas of the universe.

Navigation should be:

- Simple.
- Predictable.
- Always available.
- Visually subtle.

The content remains the main experience.

---

# Main Application Structure

AstroAlert follows a consistent structure.

## Global Navigation

Provides access to the main experiences.

Examples:

- Home.
- Planets.
- ISS.
- Eclipses.
- Telescope.
- Discover.

---

## Main Experience Area

The central area where the user explores information.

This area receives the highest visual importance.

---

## Supporting Information Area

Additional details that enhance understanding.

Examples:

- Facts.
- Explanations.
- Related discoveries.

# Layout Patterns

## Exploration Layout

Used for:

- Planets.
- Space objects.
- Discoveries.

Characteristics:

- Large visual focus.
- Supporting information.
- Interactive exploration.

---

## Data Layout

Used for:

- ISS tracking.
- Astronomical measurements.
- Real-time information.

Characteristics:

- Clear hierarchy.
- Strong readability.
- Organized data.

---

## Learning Layout

Used for:

- Educational content.
- Astronomy explanations.

Characteristics:

- Progressive information.
- Visual support.
- Easy reading.

---

## Immersive Layout

Used for:

- Featured discoveries.
- Major astronomical events.

Characteristics:

- Large visuals.
- Minimal distractions.
- Emotional experience.

---

# Responsive Principles

AstroAlert must preserve the feeling of exploration across devices.

Desktop:

More space for discovery and comparison.

Tablet:

Balanced interaction and exploration.

Mobile:

Focused experiences with clear priorities.

The universe should remain accessible anywhere.

---

# Layout Rules

## Rule 1

The most important information must be visible immediately.

---

## Rule 2

Do not overcrowd screens.

Space is part of the design.

---

## Rule 3

Every section must have a clear purpose.

---

## Rule 4

Consistency is more important than individual creativity.

---

# Design Implications

The layout system influences:

- Every page.
- Navigation.
- Components.
- Information hierarchy.
- Responsive behavior.
- User experience.

No screen should be designed independently.

Every page must feel like part of the same universe.
